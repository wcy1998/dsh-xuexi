# 05 — 创建与恢复

对应总览：[从创建到能说话](./00-总览.md#lifetime) · [拆掉](./00-总览.md#dispose)

创建逻辑由实现了 `AgentFactory` 的插件提供（通常是 `dsh-agent-loop`），通过 `ctx.agents.setFactory(...)` 挂上。  
这样 UI / ACP 只依赖 `ctx.agents.create` / `resume`，不必 import 循环包。

## 工厂槽

```text
setFactory(factory)   → 只能有一个；第二个会抛错
dispose 工厂注册      → 槽位清空
未 set 就 create      → 报错：先加载 agent-loop 之类插件
```

## `create` 在干什么（概念顺序）

```text
准备身份 sessionId、可选 meta / seed / agentOptions
  → 造出未发布的 agentCtx
  → await setup(agentCtx)     // 组合工具、监听器等；此时外界还看不见
  → 可选 setupCommit.commit() // 发布前最后一刻同步校验
  → 进入会话存储 + 注册表（enter）
  → announce → agent/created
  → agent/session-start       // 第一个「可以 inject 启动上下文」的通知点
  → 启动循环
  → 返回 AgentHandle { agent, dispose }
```

要点：

- **Setup 只组合，不驱动**。真正 `followup` 等应在 Promise resolve 之后。  
- 同 id **不能**两人同时发布：可以并行准备，只有一个能 `enter`；失败者回滚自己的私有世界。  
- 创建专用 `signal`：只取消「尚未发布」的 setup；返回 handle 之后改用 `dispose()` / `cancel()`。

## `resume`

先按 `resumeSessionId` 加载持久会话，再走类似的「未发布 setup → 发布」序列。  
没配会话持久化，或没工厂，都会拒绝。

## `AgentHandle` 与谁能拆掉

```text
AgentHandle.dispose()
  → 停循环 → 等退出 → 注销 Agent
  → 从存储移除会话 → 撤销作用域世界
```

| 你持有什么 | 能否 teardown |
|------------|----------------|
| `AgentHandle` | 能（消费方能力） |
| 仅 `ctx.agents.get(id)` 得到的裸 `Agent` | 不能靠这个 disposer 拆（观察者） |

调用方 fiber 与工厂提供方是结构化共同拥有者：卸载任一方都可能停掉相关实例。  
配置启动时由循环 fiber 拥有的 Agent，不一定暴露给外界一个 handle。

## `AgentOptions`（创建时）

```text
provider? / model? / maxTokens?
```

显式选项优先；省略则适配器或提供方默认。循环会把生效的输出上限记进请求 header。
