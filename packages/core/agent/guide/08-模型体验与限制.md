# 08 — 模型体验与已知限制

对应 README 后半：这些内容决定「模型实际吃到什么」以及「现在还做不到什么」。

## 模型体验（压缩版）

### 用户 / steering / inject

- `send` / `steer` / `inject` 把输入送进所属会话。  
- `agent/pre-step` 等可以拒绝步骤或改批次；**本包不塞固定提示词文案**。  
- **已接受**的内容进入历史或前缀 → 占 token；**被挡住**的不进请求。  
- 已接受历史与 steering 倾向追加；被拒的提交不发请求。新建/恢复的实例可能形成不同前缀，影响 KV cache 复用。

### Agent 作用域组合

- 在 `agent.ctx` 注册的段、工具、拦截器只影响该 Agent，dispose 后消失。  
- 本包本身不「加 token」；变的是该 Agent 的组装结果。  
- 作用域注册稳定 → 前缀稳定；改段/工具/请求监听器可能从第一个受影响 token 起让缓存失效。

## 扩展点提醒

| 你想做的事 | 走哪里 |
|------------|--------|
| 程序化新建/恢复并拥有 dispose | `ctx.agents.create` / `resume` |
| 换循环但仍兼容生态 | 实现 `Agent` + `register`，事件名沿用本包声明 |
| 听生命周期 / 拦截步骤 | `agent/*` 事件（无需依赖 loop 包） |
| subagent 委派 | **不是** `Agent` 上的方法；经工厂造普通 handle，传输在核心接口之外 |

## 已知限制（人话）

1. **发起方作用域出不了进程** — 跨进程自己带身份。  
2. **环境里还挂着 Agent 引用，不代表还能安全用** — 先看 status / 取消 / 能力。  
3. **Agent 之间除委派外的通道**（共享状态、子输出流、后台轮询）还不在当前 `ctx.subagents` 能力里。  
4. **`agent/session-start` 挡不住启动** — 它只是通知；发布前必须就绪的异步组合放进 `setup`。  
5. **`cancel()` 默认清空 inbox** — 要保留排队用 `{ keepInbox: true }`；还没有「只停当前 step、本轮 turn 继续」的 API。  
6. **每条 `UserMessage` 只有一个 `MessageSource`** — 多插件揉进同一次工具贡献时，无法列出多个生产者。  
7. **`SessionStartSource` 的 `'clear'` / `'compact'` 尚无发出方** — 实际多见 `'startup'` / `'resume'`。
