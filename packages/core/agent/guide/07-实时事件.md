# 07 — 实时事件 `agent/*`

这些事件让插件协作，又**不必依赖**具体循环包。  
签名与分发 mode 的生成表见 [core.md](../../../../docs/subsystems/core.md#cordis-surface)；与持久 turn 流的先后见 [架构轮次流](../../../../docs/architecture.md#turn-flow)。

## 两套账不要混

| 种类 | 例子 | 用途 |
|------|------|------|
| 实时 `agent/*` | `agent/created`、`agent/pre-step` | 进程内协调、拦截 |
| 持久 session 事件 | `turn/start`、`step/start`、`assistant/chunk` | 历史、重放、UI 时间线 |

Token 流、turn/step 边界**不会**再镜像成一套 `agent/*`。工具策略在 [`dsh-tools`](../../tools/README.md)。

## 生命周期（通知 emit）

```text
setup 完成且会话+注册表都进场
  → agent/created
  → agent/session-start   // 不可否决；可 inject 启动上下文
  …

离开注册表
  → agent/disposed        // Loop 在驱动器停稳后发；之后可能还在拆 session/作用域
```

`agent/status`：`idle` ⇄ `running`。

Inbox 实时：`inserted` / `claimed` / `discarded`（每条消息一份最小载荷）。

出错通知：`agent/error`。

## 拦截点（你最常写监听器的地方）

### `agent/pre-step`（waterfall）

即将进入一个模型步骤前：payload 含已领取的 `messages`、`turn`、`step`、`signal`。

返回：

- `{ kind: 'reject' }` — 本步不进模型（已领取的消息不退回 inbox）  
- `{ kind: 'enter', messages }` — 用这批（可改写）进入  

调用 `next()` 表示沿用下游决定。  
工具要求「继续请求」时，批次也可以是空的。

### `agent/request`（waterfall）

替换本步的 LLM 调用配置。不能靠它改消息内容；模型可见内容走已记录的通道。

### `agent/request-error`（waterfall）

模型请求失败后的恢复：拥有恢复权的监听器返回 `{ kind: 'retry' }` 且**不要**调用 `next()`。  
默认落到终端失败。

### `agent/turn-stopping`（serial）

这一轮「本可以结束」时再问一遍。监听器可以再 `steer(...)`；机器重读 inbox——有新 steering 就再跑 step，没有就关 turn。  
结果由 inbox **数据**决定，不靠监听器谁先谁后抢输赢。

## 关于 `AbortSignal`

轮次相关扩展点会带上当前 turn 的 signal。  
监听器可以配合它取消自己的活，但**不要**把它存下来当成控制**下一轮**的权限。

## 作用域过滤

在 `agent.ctx` 上注册的监听器，通常只收到**这个** Agent 的事件。  
用 `agentEvents` 分发时，载体与 payload.agent 绑在一起。
