# 06 — 发起方作用域（Initiator）

问题：工具、钩子、深层 helper 在 `await` 之后，怎么还知道「这次驱动是哪个 Agent 引起的」？

办法：进程内用 `AsyncLocalStorage` 带着发起方 `Agent`（不是只带一个字符串 id）。

## 四个 API

| API | 行为 |
|-----|------|
| `currentInitiator()` | 有就返回，没有就 `undefined`（适合日志/指标） |
| `requireInitiator()` | 没有就抛 `no initiating agent is active` |
| `withInitiator(agent, fn)` | 在这段（及其 await 延续）里继承该 agent |
| `withoutInitiator(fn)` | 故意清空，避免共享定时器/队列泵「误继承」碰巧在场的 Agent |

## 父子驱动器互不抢戏

```text
父 withInitiator(父) 里启动子驱动器
  → 子边界内：发起方是子
  → withInitiator 返回后：父 continuation 立刻回到父
  → 系统仍会等到子的 Promise 结算（drain），再算父侧边界结束
```

创建、读持久化、未发布的 setup 在**子边界之外**：  
父发起的 setup 里，`currentInitiator()` 往往是**父**（谁引起的），而 `agentCtx.agent` 是**子**（正在组合谁）。

## 必须记住的限制

1. **只在本进程有效。** 跨 worker / HTTP / 队列 / 重启，要自己在请求里带显式身份。  
2. **「ALS 里有 Agent」≠ 还活着 ≠ 已授权。** 敏感操作仍要看 `status`、取消态、能力约定。  
3. **服务卸载时**：拒新边界 → 等返回了 Promise 的边界 drain → 禁用存储。没通过返回值挂上的「扔出去的活」仍归扔出它的子系统。  
4. 若某条继承链正在 unload **拥有自己的** fiber，会把这条嵌套链从 drain 里放开，避免「等自己卸完」卡死。

详细约定见 [发起方作用域决策](../../../../.agents/notes/implemented/architecture/2026-07-15-agent-initiator-scope.md)。

## 小例子

```text
// 驱动器外包一层
await ctx.agents.withInitiator(agent, async () => {
  await runTools()           // 深处 requireInitiator() 仍是这个 agent
})

// 启动全局泵时不要继承
ctx.agents.withoutInitiator(() => {
  startSharedQueuePump()
})
```
