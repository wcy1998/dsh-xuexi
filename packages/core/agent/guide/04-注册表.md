# 04 — 注册表 `ctx.agents`

对应总览：[对象关系](./00-总览.md#objects) · [三层「当前是谁」](./00-总览.md#who)

`AgentRegistry` 挂在 Cordis 的 `ctx.agents` 上，做三件大事：

1. 记住本进程里**活着的** Agent  
2. 把「创建/恢复」委托给循环工厂  
3. 在异步调用链里携带「是谁发起的」（见 [06](./06-发起方作用域.md)）

## 查找

```text
ctx.agents.get(id)      → 活 Agent，没有则 undefined
ctx.agents.list()       → 全部，按注册顺序
ctx.agents.roots()      → 创建时没有「父 Agent 上下文」的顶层
ctx.agents.isOwnedBy(childId, parent)
                        → 这个活条目是不是经 parent 的作用域创建的
```

### 两个容易混的「父子」

| 概念 | 问的是什么 |
|------|------------|
| 运行时 `owner`（`isOwnedBy` / `roots`） | 创建时有没有父 Agent 的 scoped context |
| 持久 `parentSession`（会话 meta） | 磁盘上的会话谱系 / fork 关系 |

从磁盘 resume 回来的 fork，谱系上可能有父会话，但运行时仍可能是 `roots()` 之一。

## Agent 自己的小世界：`agent.ctx`

```text
在 agent.ctx 注册工具 / 提示词段 / 监听器
  → 只对该 Agent 生效
  → dispose 时全部撤销
```

分发事件时，常用 `agentEvents(ctx, agent)`：自动带上正确的 scope 载体，并在 payload 里注入同一个 `agent`，避免「听的是 A、payload 写成 B」。  
组装提示词用 `assembleContextFor(agent)`，同时带上 `agent` 与 `scope`。

运行中切换模型：`installModelSelection(agentCtx, selection)` 会在组装时拍快照，并让同一步的请求路由用同一快照（详见 [`../src/model-selection.源码解析.ts`](../src/model-selection.源码解析.ts)）。

## 登记已有 Agent

### 普通路径：`register(agent)`

「Agent 已经构造好了，请记一笔。」  
内部会插入并广播 `agent/created`；调用方 fiber dispose 时成对 `agent/disposed`。

### 高级路径：`enter` → `announce`（异步工厂用）

需要「先 setup、对外还看不见，再一锤定音发布」时：

```text
1. enter(agent, owner)
   - 检查 id === session.id
   - 同 id 已存在则失败（权威冲突点）
   - 先不发 created
   - 返回 detach（可撤销这笔插入）

2. … 做发布前的其它步骤 …

3. announce(agent)
   - 恰好发一次 agent/created
```

若某个 `agent/created` 监听器在分发过程中请求 detach，会等到**这次分发全部听完**再删，避免后半截监听器看到幽灵状态。  
陈旧的 detach 删不掉「后来同 id 的新条目」（按条目对象身份校验）。

普通插件用 `register` 即可，不必手写 enter/announce。
