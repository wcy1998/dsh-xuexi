# 01 — 这是什么

## 一句话

`@deepseek-ai/dsh-agent` 定义：**插件怎么拿到一个 Agent、怎么跟它说话、生命周期事件叫什么名字**。  
它**不包含**「怎么一轮轮调模型」——那是 `dsh-agent-loop` 的事。

可以把它想成：

| 角色 | 类比 |
|------|------|
| `dsh-agent` | 遥控器说明书 + 设备登记册 |
| `dsh-agent-loop` | 具体哪台电视机的内部电路 |
| UI / ACP / 钩子 | 按说明书按按钮的人 |

换一台「电视机」（换循环实现）时，只要仍提供同一套 `Agent` 接口，遥控器用法不变。

## 你在代码里会碰到什么

1. **`Agent`**：一个活的智能体把手（发消息、取消、看 status）。
2. **`ctx.agents`（`AgentRegistry`）**：本进程里有哪些活 Agent；以及如何 create/resume。
3. **`agent/*` 事件**：进程内协调用（创建了、状态变了、能否进下一步…）。
4. **会话日志里的事件**（如 `turn/*`、`agent/inbox/spliced`）：可持久、可重放的真相。

实时 `agent/*` 和持久 `session` 事件是两套东西：前者方便插件协作，后者负责「事后还能还原」。

## 可选诊断

`@deepseek-ai/dsh-agent/invariant` 会检查诸如「不要重复发同一个 status」这类关系。  
根服务**不会**自动加载它；需要诊断时再显式挂上。
