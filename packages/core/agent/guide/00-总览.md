# 00 — 总览：先把图看懂

后面每一章都是这几张图上的一块。卡住时回到这里对位置。

本包只定义**接口、登记册、inbox、发起方作用域、`agent/*` 事件名**。真正一轮轮调模型的是 `dsh-agent-loop`（图里叫「驱动器」）。更细的官方轮次图：[架构 · 轮次流程](../../../../docs/architecture.zh.md#turn-flow)、[时序图](../../../../docs/agent-lifecycle.zh.md)。

一张图记住一生（细节在后面各节展开）：

  P --> A["announce<br/>agent/created<br/>agent/session-start"]
  A --> I["idle"]

  R --> T["一轮 turn"]

## 1. 对象关系：谁挂在谁身上

```mermaid
flowchart TB
  UI["UI / ACP / 钩子"]
  CTX["全局 ctx"]
  REG["ctx.agents<br/>AgentRegistry"]
  FAC["AgentFactory<br/>通常 dsh-agent-loop"]
  ALS["发起方作用域 ALS<br/>只在本进程"]

  UI -->|"create / followup / 听事件"| REG
  CTX --> REG
  REG --> FAC
  REG --> ALS

  subgraph one["一个活 Agent（id = session.id）"]
    A["Agent 把手"]
    S["session<br/>日志 = 权威记录"]
    IB["inbox<br/>两列待处理投影"]
    AC["agent.ctx<br/>这间房专用"]
    ST["status idle | running"]
    A --> S
    A --> IB
    A --> AC
    A --> ST
    S -->|"持久 agent/inbox/spliced"| IB
  end

  REG -->|"get / list / roots"| A
  FAC -->|"实现 Agent 并开车"| A
  H["AgentHandle"] -->|"agent + dispose"| A
```

读图口诀：

| 你拿到的 | 它是什么 | 细节 |
|----------|----------|------|
| `Agent` | 遥控器 | [02](./02-Agent把手.md) |
| `inbox` | 两列订单架（内存视图） | [03](./03-Inbox收件箱.md) |
| `ctx.agents` | 本进程登记册 + 创建入口 | [04](./04-注册表.md) |
| `AgentHandle` | 遥控器 **加上** 拆掉的权利 | [05](./05-创建与恢复.md) |
| 发起方 ALS | `await` 链上「是谁引起的」 | [06](./06-发起方作用域.md) |
| `agent.ctx` | 只属于这个 Agent 的 Cordis 世界 | [04](./04-注册表.md) |

两个容易混的「父」：**运行时 owner**（`roots` / `isOwnedBy`）问创建时有没有父 Agent 的 scoped context；**持久 `parentSession`** 问磁盘上的会话谱系。从磁盘 resume 回来的 fork，谱系上可以有父会话，运行时仍可能是 `roots()` 之一。

## 2. 两套账：实时通知 vs 持久日志

```mermaid
flowchart LR
  subgraph live["实时 agent/* · 进程内协作"]
    L1["created / disposed / status"]
    L2["inbox inserted / claimed / discarded"]
    L3["pre-step / request / request-error / turn-stopping"]
  end

  subgraph dur["持久 session · 可重放真相"]
    D1["agent/inbox/spliced"]
    D2["turn/*  step/*"]
    D3["user/message  assistant/*  tool/*"]
  end
```

Token 流、turn/step 边界**不会**再镜像成一套 `agent/*`。插件拦截走左边；UI 时间线、恢复、对账走右边。事件名与拦截点：[07](./07-实时事件.md)。

## 3. 从创建到能说话

`create` / `resume` 都走工厂。外界在 `announce` 之前看不见这个 Agent。

```mermaid
sequenceDiagram
  participant UI as 调用方
  participant REG as ctx.agents
  participant FAC as AgentFactory
  participant SETUP as setup
  participant STORE as 会话存储
  participant LOOP as 驱动器

  UI->>REG: create / resume
  REG->>FAC: 委托工厂
  FAC->>FAC: 造未发布的 agentCtx
  FAC->>SETUP: await setup(agentCtx)
  Note over SETUP: 只组合工具/监听器<br/>此时还不能 followup
  SETUP-->>FAC: 可选 commit()
  FAC->>STORE: enter(session)
  FAC->>REG: enter(agent)
  FAC->>REG: announce
  REG-->>UI: agent/created
  FAC-->>UI: agent/session-start
  Note over UI: 第一个可 inject 启动上下文的点<br/>挡不住启动
  FAC->>LOOP: 启动循环
  FAC-->>UI: AgentHandle
```

同 id 可以并行准备，只有一个能 `enter`；失败者回滚自己的私有世界。创建专用 `signal` 只取消「尚未发布」的 setup；返回 handle 之后改用 `dispose()` / `cancel()`。完整约定：[05](./05-创建与恢复.md)。

## 4. 用户发一条消息之后

这是日常主路径。驱动器细节以官方轮次图为准；这里只标本包的词汇嵌在哪。

```mermaid
sequenceDiagram
  participant U as 用户或插件
  participant A as Agent
  participant IB as inbox
  participant D as 驱动器
  participant H as agent/* 监听器
  participant LOG as 会话日志
  participant LLM as 模型

  U->>A: followup / steer / inject
  A->>IB: 写入 next-turn 或 next-step
  IB->>LOG: agent/inbox/spliced
  A-->>H: agent/inbox/inserted
  alt followup 或 steer
    A->>D: 唤醒
    D-->>H: agent/status running
  else inject
    Note over A,IB: 不唤醒；idle 时一直躺着
  end

  D->>LOG: turn/start
  D->>IB: claim 全部 next-step<br/>若需要再加一条 next-turn
  IB->>LOG: spliced 纯删除
  D-->>H: agent/inbox/claimed
  D->>H: agent/pre-step waterfall

  alt reject 或首批被改空
    Note over IB: 已 claim 的不退回、不发 discarded
    D->>LOG: turn/end 无 step
  else enter(messages)
    D->>LOG: step/start
    D->>LOG: user/message
    D->>H: agent/request waterfall
    D->>LLM: llm/stream
    LLM-->>LOG: assistant/chunk* / assistant/message
    Note over D,LOG: 工具走 dsh-tools 流水线
    D->>LOG: step/end
    opt 本可结束
      D->>H: agent/turn-stopping serial
      Note over H: 可再 steer；有新 next-step 就再跑 step
    end
  end

  D->>LOG: turn/end
  D-->>H: agent/status idle
```

`followup` **不**返回「这轮做完了」。消息 id 只标识 inbox 的插入 / 领取 / 丢弃；输出去看会话事件。要等整机停稳用 `whenIdle()`。`running` 覆盖收尾、落盘、连续排队的多轮，不等于「某个 turn 一定还开着」。

## 5. 三条进 inbox 的路

```mermaid
flowchart TB
  F["followup"] --> NT["next-turn 主单"]
  ST["steer"] --> NS["next-step 小条"]
  IN["inject"] --> NS
  F --> W["唤醒驱动器"]
  ST --> W
  IN --> NW["不唤醒"]

  W --> CLAIM["步骤边界 claim"]
  NW --> WAIT["等到下次 followup/steer"]
  WAIT --> CLAIM

  CLAIM --> ALLNS["先取走全部 next-step"]
  ALLNS --> ONENT["若本步需要主单：再取 1 条 next-turn"]
```

`claim` 是循环内部操作；插件日常只用 `followup` / `steer` / `inject`。领取 vs 取消：[03](./03-Inbox收件箱.md)。

<a id="who"></a>

## 6. 三层「当前是谁」不要混

```mermaid
flowchart TB
  G["全局 ctx"] -->|"create 时挂出"| AC["agent.ctx<br/>工具 / 段 / 监听器只对它生效<br/>dispose 全部撤销"]
  ALS["withInitiator(agent)<br/>本进程 await 链"] -->|"requireInitiator()"| WHO["这次驱动是谁引起的"]
  AC -->|"agentCtx.agent"| CHILD["正在组合/驱动哪一个"]
```

创建、读持久化、未发布的 setup 在**子发起方边界之外**：父发起的 setup 里，`currentInitiator()` 往往是父，而 `agentCtx.agent` 是子。ALS 出不了进程，有 Agent 也不等于还活着或已授权。[06](./06-发起方作用域.md)。

<a id="dispose"></a>

## 7. 拆掉

```mermaid
sequenceDiagram
  participant O as 持有 Handle 的一方
  participant H as AgentHandle
  participant D as 驱动器
  participant REG as ctx.agents
  participant STORE as 会话存储
  participant AC as agent.ctx

  O->>H: dispose()
  H->>D: 停循环并等退出
  H->>REG: 注销 → agent/disposed
  H->>STORE: 移除会话
  H->>AC: 撤销作用域世界
```

只有 `AgentHandle.dispose()` 是消费方拆机能力；`ctx.agents.get(id)` 拿到的裸 `Agent` 不能靠这个 disposer 拆。调用方 fiber 与工厂提供方是结构化共同拥有者。
