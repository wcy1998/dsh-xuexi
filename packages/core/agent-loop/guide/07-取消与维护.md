# 07 — 取消与维护

对应总览：[取消](./00-总览.md#cancel)

## `cancel(cause, options?)`

| 行为 | 说明 |
|------|------|
| 默认 | 清空 inbox + abort 当前活动 signal |
| `{ keepInbox: true }` | 只 abort，排队消息保留 |
| 已 idle | **空操作**（不预武装以后的运行） |

`cause` 影响报告（`turn/end` 的 aborted/disposed 等），不改变「取消后才完成的结果上下文」如何处理。

## Wake 锁存（cancel 收敛窗口）

cancel 后、活动尚未收敛到 idle 前，又来了唤醒输入：

```text
不能进已死的活动
  → wakeRequested = true（锁存）
  → 驱动器收敛到 idle 时，若 inbox 仍有活 → 自动 wakeDriver
  → 无需再发一条唤醒 send
```

例外：`disposed` 取消**从不**锁存。已 idle 时发的唤醒总是打开自己的 turn 边界（即使消息已被清，也可能看到瞬态 `idle → running → idle`）。

已 abort 活动中的唤醒 send 会改投 `next-turn`，避免塞进当前死 turn。

## `runMaintenance`

真正 idle 时跑一段**非对话**异步活（如整理缓存）：

- 对外 `status` 仍是 `idle`
- 期间唤醒消息待在 inbox；维护结束若 `wakeRequested` 再处理
- 已在跑 turn 或已有维护 → 同步抛错

## dispose

等忽略信号的工作完成，再从注册表移除；有序 teardown 见 [02](./02-AgentLoop服务.md)。
