# 04 — 一轮对话（turn / step）

对应总览：[一轮 turn](./00-总览.md#turn)

官方细图：[架构 · 轮次流程](../../../../docs/architecture.zh.md#turn-flow)、[agent-lifecycle](../../../../docs/agent-lifecycle.zh.md)。这里标本包代码路径。

## 名词

| 词 | 含义 |
|----|------|
| **turn** | 零个或多个 step；`turn/start` 后打开，不再欠活时 `turn/end` |
| **step** | 一次模型请求 + 它触发的工具 |
| **claim** | 从 inbox 取批：先全部 `next-step`，若本边界需要再加 1 条 `next-turn` |

## `turn()` 主循环（概念）

```text
turn/start
target = next-turn   // 首步：主单 + 小条；之后步骤只领 next-step
loop:
  preStep(target) → reject | enter(messages, assembly)
  reject → turn/end blocked，本轮结束
  首步且 messages 空 → turn/end completed（空转，无模型调用）
  step/start
  写入 user/message
  step(assembly) → 模型 + 工具
  step/end
  若本可结束且 next-step 空：
    agent/turn-stopping（可再 steer）
  若仍可结束且 next-step 空 → break
  target = next-step
turn/end(reason)
若 inbox 仍有活 → 换新 AbortController，继续下一 turn（kick 循环）
```

## `preStep`

1. `inbox.claim(target, turn)` —— 纯删除 splice + `agent/inbox/claimed`
2. 可选：把动态 runtime context 快照塞进批次（[`RuntimeContextProjection`](../src/runtime-context.ts)）
3. `agent/pre-step` waterfall → `reject` 或 `enter(messages)`
4. enter 时组装 `systemPrompt`（`assembleContextFor`）

拒绝后：已 claim 的消息**不退回** inbox；关无 step 的 turn（通常 `blocked`）。

## step 结束与 turn 结束原因

| 情况 | 大致 reason |
|------|-------------|
| 正常、无更多 next-step | `completed` |
| 触达输出上限 | `max-tokens`（粘性：后续 completed 不降级） |
| pre-step 拒绝 | `blocked` |
| cancel | `aborted` / `disposed` 等 |
| 未捕获失败 | `error` |

插件失败通常结束**当前 turn**，不拆掉整个循环。
