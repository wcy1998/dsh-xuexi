# 05 — 模型请求

对应总览：[一轮 turn](./00-总览.md#turn)

每一步：组装 prompt → `agent/request` → `prepareCall` → 流式 → 记 `assistant/*`。

## 组装与变量

本包提供提示词变量：`provider`、`model`、`cwd`。不塞固定 persona 文案（部署 persona 在 `dsh-system-prompt`）。

`system-prompt/assemble` 可被插件改写；改写者负责协议连贯。入口可用 [`installModelSelection`](../../agent/src/model-selection.ts) 在同一步锁定选型。

## `agent/request` → `prepareCall`

```text
header 提案（去掉 adapterDefaults 标过的字段，让新路由重填默认）
  → agent/request waterfall（可换 LlmCallConfig）
  → ctx.llm.prepareCall()（校验适配器字段、填 reasoning / maxTokens 默认）
  → 记 request/header（生效配置 + 哪些字段来自适配器）
  → llm/stream（或 preparedCall.stream）
```

准备完成的调用在解析、记 header、分派期间**钉死同一适配器注册**，避免 HMR 把 A 适配器能力与 B 适配器请求混用。

无适配器的路由可保留配置，让 `llm/stream` 监听器短路；未处理最终仍 `NO_ADAPTER`。

## 流式与 `assistant/message`

- 每个 chunk → `assistant/chunk`
- 提供方成功结束 → 恰好一条 `assistant/message`（含无内容、`max-tokens`）
- `sourceEventSeqs` 列出分片 seq；空流为 `[]`
- 空内容不进派生历史，但事件保留用量等

取消打断流时：若已有非空文本/推理送达用户，仍可追加 `interrupted: true` 的锚点，让下次请求包含用户见过的前缀。未分派工具调用省略；提供方故障不提交 assistant 内容。

## 请求必须可从日志重建

模型可见 ⟺ 已记录。可选 invariant 检查：`llm/stream` 上的循环请求须 frozen、带 live `sessionId`，且 `messages` / header 与 `deriveMessages()` / `foldRequestHeader` 一致。见 [`invariant.ts`](../src/invariant.ts)。
