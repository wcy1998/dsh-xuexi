# 02 — 两层默认值

对应总览：[两层来源](./00-总览.md#layers)

## 底层：Cordis 组合项

插件 `Config` **必须**提供：

```text
{ provider: string, model: string }
```

在 [`dsh-base`](../../../bundle/base/cordis.patch.yml) 里类似：

```yaml
- id: agent-default-model
  name: '@deepseek-ai/dsh-agent-default-model'
  config:
    provider: deepseek-official
    model: deepseek-v4-flash
```

这层是 **Settings 分节的 `base`**，也是 **没有 Settings 提供方时的唯一来源**。

### 为什么组合项不含 `reasoningEffort`

| 若在组合 config 里写 effort | 实际设计 |
|-----------------------------|----------|
| 用户换模型后清 effort，卸载 Settings 又继承回 config | effort 只存在于 Settings 分节 |
| `saveSelection` 无法表达「完整选择但无 effort」 | 保存时省略字段即清除 |

组合项只保证「部署总能跑起来有一个 provider/model」。

## 上层：Settings 分节

命名空间：`agent-default-model`（常量 `AGENT_DEFAULT_MODEL_SETTINGS_NAMESPACE`）。

Schema：

```text
provider: string   （必填）
model: string      （必填）
reasoningEffort?: string
```

挂载 [`dsh-settings-file`](../../../settings/settings-file/README.md) 等提供方后，用户层存在 `$DSH_HOME/settings.yaml`；Web Models 页通过 ApiProxy 写这一分节。

## 怎么叠：`installSettingsSection`

构造 `AgentDefaultModelConfig` 时：

```text
1. entry = { provider, model } 来自插件 config
2. source = () => entry            初始只读组合项
3. installSettingsSection(..., entry, {
     setSource: (current) => { source = current },
     onChange: () => {},           // 无注册级缓存，每次 currentSelection 现读
   })
4. settings 挂上后：setSource(() => scope.get())
5. settings 卸载后：setSource(() => entry) 回退组合项
```

因此：

- **部分写入**合法：只改 `model` 时 `provider` 仍从 base 继承（测试 `layers a hand-written partial section`）。
- **Settings fiber dispose** 后，`currentSelection()` 回到 cordis 组合项，不会卡在旧用户值。

## 小例子

```text
组合项：deepseek-official / deepseek-v4-flash

用户 saveSelection → acme-gateway / acme-large / high
  → currentSelection() = 三者皆有

用户再 saveSelection → acme-gateway / acme-plain（无 effort）
  → reasoningEffort 被清掉

Settings 提供方卸载
  → currentSelection() = deepseek-official / deepseek-v4-flash
```
