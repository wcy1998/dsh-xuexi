# 06 — 模型体验与已知限制

对应总览：[优先级](./00-总览.md#precedence)

## 模型体验（压缩版）

### 间接影响

本包不组装 prompt、不调用 LLM。它只决定**入口交给 Agent 的 provider/model（及可选 effort）**；可见请求由 `system-prompt/assemble`、`agent/request` 与适配器完成。

### Token / 历史

已建立会话：选型以**请求日志**为准；改 `currentSelection()` **不会** retroactively 改已有 `user/message` / assistant 历史。

### KV Cache

| 操作 | 影响 |
|------|------|
| 改进程默认 | 仅之后从新默认 resolve 的 Agent / 空白 fallback |
| 已有 session 且 header 已记模型 | 前缀保持稳定，本服务不使其失效 |

## 已知限制（人话）

1. **只拥有一项进程级默认** — 每个会话的运行中选型仍是入口（ApiProxy `selectionFor`）的责任。  
2. **无 Settings 时 `saveSelection` 无效** — 无法跨重启保留用户改过的默认。  
3. **不校验目录成员** — 配了不存在的 model id，失败在真正 `llm/stream` 时由消费方诊断。  
4. **组合 config 不含 reasoningEffort** — 部署方不能单靠 cordis 配 effort；要走 Settings 或入口代码。  
5. **与 Agent 包解耦** — 必须配合 `installModelSelection` 才能把 effort 等同一步请求；只写 `agentOptions` 不够表达 effort 的运行时语义。
