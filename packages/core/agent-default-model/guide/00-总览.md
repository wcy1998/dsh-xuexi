# 00 — 总览：先把图看懂

后面每一章都是这几张图上的一块。卡住时回到这里对位置。

本包只管**进程里一份共享的默认模型选择**（`provider` / `model` / 可选 `reasoningEffort`）。它**不**驱动 Agent 循环、**不**校验目录里有没有这个模型；入口在**创建尚无会话级选型的 Agent** 时读它，再通过 [`dsh-agent` 的 `installModelSelection`](../../agent/src/model-selection.ts) 挂到单个 Agent 上。

<a id="process-vs-session"></a>

### 进程共享 ≠ 所有会话共用

**进程共享**只描述 `ctx.agentDefaultModel`：全进程一份默认来源。每个 Agent 仍有自己的 `session`、inbox 与（日志记下后的）模型选型；详述见 [01 — 进程共享](./01-这是什么.md#process-vs-session)。

```mermaid
flowchart TB
  PROC["一个 dsh 进程"]
  ADM["ctx.agentDefaultModel<br/>一份默认"]
  REG["ctx.agents"]
  A["Agent / session A"]
  B["Agent / session B"]

  PROC --> ADM
  PROC --> REG
  REG --> A
  REG --> B
  ADM -.->|"仅 fallback"| A
  ADM -.->|"仅 fallback"| B
```

<a id="layers"></a>

## 2. 两层默认值从哪来

```mermaid
flowchart TB
  subgraph base["底层：组合配置（cordis）"]
    C["provider + model<br/>reasoningEffort 故意不在此"]
  end

  subgraph user["上层：Settings（可选）"]
    S["provider / model / reasoningEffort?<br/>完整保存、可清空 effort"]
  end

  base --> MERGE["installSettingsSection<br/>base + scope.get()"]
  user --> MERGE
  MERGE --> OUT["currentSelection()<br/>返回独立副本"]
```

`reasoningEffort` 只在 Settings 分节里：用户换到不支持推理强度的模型时，必须能**清掉**旧 effort；若写进组合 config，卸载 Settings 后又会继承回来。

<a id="read"></a>

## 3. 读：`currentSelection()`

```mermaid
sequenceDiagram
  participant EP as 入口 headless / ApiProxy
  participant ADM as agentDefaultModel
  participant SRC as source 闭包
  participant SET as settings scope

  EP->>ADM: currentSelection()
  ADM->>SRC: source()
  alt 已挂载 settings 且分节有值
    SRC->>SET: scope.get() 与 base 合并
    SET-->>ADM: AgentDefaultModelSettings
  else 无 settings 或已卸载
    SRC-->>ADM: 组合 config 条目
  end
  ADM-->>EP: ModelSelection 副本
```

每次调用都**现读**；没有进程内缓存。Settings 文档热更新后，下一次 `currentSelection()` 即见新值。

<a id="write"></a>

## 4. 写：`saveSelection()`

```mermaid
sequenceDiagram
  participant UI as Web Models 页 / RPC
  participant API as ApiProxy
  participant ADM as agentDefaultModel
  participant SET as ctx.settings

  UI->>API: 切换默认模型
  API->>ADM: saveSelection(完整 ModelSelection)
  alt settings 提供方已挂载
    ADM->>SET: replace(agent-default-model, …)
    Note over ADM: 下次 currentSelection 读用户层
  else 无 settings
    ADM-->>API: 空操作
    Note over ADM: 组合 config 仍为权威
  end
```

未挂载 Settings 时 `saveSelection` **静默 no-op**——不是抛错，而是无法跨进程/重启保留用户选择。

<a id="consumers"></a>

## 5. 入口怎么消费（创建新 Agent）

```mermaid
sequenceDiagram
  participant EP as headless / ApiProxy
  participant ADM as agentDefaultModel
  participant REG as ctx.agents
  participant SETUP as setup(agentCtx)
  participant AG as Agent

  EP->>ADM: currentSelection()
  ADM-->>EP: { provider, model, reasoningEffort? }
  EP->>REG: create({ agentOptions: { provider, model }, setup })
  REG->>SETUP: installModelSelection(agentCtx, ref)
  Note over SETUP: ref.current 初始化为刚读到的默认
  REG-->>EP: AgentHandle
  EP->>AG: followup / 业务消息
```

headless 在 Loader 结算后才创建 Agent；ApiProxy 在每次 create/resume 的 `agentOptions()` 里**重新**读默认，避免 stale。

<a id="precedence"></a>

## 6. 默认 vs 单个 Agent：谁赢

本包只提供**最后一档** fallback。ApiProxy 在运行中还有更高优先级：

```mermaid
flowchart TB
  P1["本进程内用户刚选的 current<br/>selectionFor(agent).current"]
  P2["会话日志里最新 request header"]
  P3["ctx.agentDefaultModel.currentSelection()"]

  P1 -->|"有则停"| USE["这一步用的 ModelSelection"]
  P2 -->|"无 P1 且有日志"| USE
  P3 -->|"空白新会话"| USE
```

已有会话、日志里已经记过 provider/model 的，**不会**因为改了进程默认而 retroactively 变模型；改默认只影响之后新 resolve 的 Agent / 空白会话。
