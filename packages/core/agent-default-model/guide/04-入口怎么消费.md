# 04 — 入口怎么消费

对应总览：[入口消费](./00-总览.md#consumers)

本包被 **inject 依赖**，不主动创建 Agent。导读里常提到的 **headless、Web、ApiProxy** 是三种不同的「怎么连上 Agent」的方式；它们都读**同一** `ctx.agentDefaultModel`，但面向的用户场景不同。

<a id="entrypoints"></a>

## 先分清：profile、bundle、网关

| 名字 | 它是什么 | 你怎么遇到它 | 和默认模型的关系 |
|------|----------|--------------|------------------|
| **headless** | 一个叫 `headless` 的 **profile / 组合包**（[`dsh-headless`](../../../bundle/headless/README.zh.md)） | 终端：`dsh --profile headless "修这个 bug"` | runner **直接** `currentSelection()` → `agents.create` → 跑完打印 stdout → 退出 |
| **Web** | 一个叫 `web` 的 **profile / 组合包**（[`dsh-web-app`](../../../bundle/web-app/README.zh.md)） | 终端：`dsh --profile web`，浏览器打开本地页面 | 不自己读默认模型；通过下面的 ApiProxy 创建/恢复会话 |
| **ApiProxy** | 宿主侧的 **API 网关服务**（[`dsh-host-apiproxy`](../../../host/apiproxy/README.zh.md)），Cordis 键 `ctx.apiProxy` | Web 前端、SDK、HTTP `/api/*` 都通过它操作会话 | **直接**消费 `currentSelection` / `saveSelection`；Models 页改默认也走这里 |

三者不是并列的三种「程序」，而是两层：

```text
dsh 进程
  ├── profile headless
  │     └── headless-runner          ← 入口：命令行一次性任务
  │
  └── profile web
        ├── webserver + 浏览器前端    ← 你看到的 Web UI
        └── ApiProxy (ctx.apiProxy)    ← 入口：RPC 创建会话、切模型、读历史…
```

共同点：都叠在 [`dsh-base`](../../../bundle/base/README.zh.md) 之上，共享 spine（`ctx.agents`、LLM、工具、**`ctx.agentDefaultModel`** 等）。headless **故意不**挂 Host、HTTP、浏览器；Web **会**挂 ApiProxy 和前端。

## headless（`dsh --profile headless`）

[`dsh-headless`](../../../bundle/headless/src/index.ts) `inject: ['agentDefaultModel', 'agents', 'sessions']`。

```text
await loader.await()                    // 等同树插件装齐
selection = agentDefaultModel.currentSelection()
agents.create({
  sessionId: 新 UUID,
  meta: { cwd },
  agentOptions: { provider, model },   // 来自 selection，不含 effort 静态字段
  setup: (agentCtx) => {
    ref = { current: selection, assembled: undefined }
    installModelSelection(agentCtx, ref)
  },
})
agent.followup(任务文本)
await whenIdle → 打印 assistant → exit
```

特点：一次进程、一个 Agent、读完默认后**不再**调用 `saveSelection`（CLI 无 Models 设置 UI）。**不开端口、无浏览器**，适合 CI / 脚本。

## Web（`dsh --profile web`）

[`dsh-web-app`](../../../bundle/web-app/README.zh.md) 在 base 上挂：HTTP 服务、静态前端、workspace、以及 **ApiProxy**。你在浏览器里聊天、开多会话、在 Models 页选模型——UI 发 RPC，**真正创建 Agent、写默认模型的是 ApiProxy**，不是前端本身。

Web profile 同样依赖 base 里的 `agent-default-model`；用户改默认会进 `settings.yaml`，ApiProxy 下次 `currentSelection()` 即见。

## ApiProxy（网关，Web 的核心入口）

[`ApiProxyService`](../../../host/apiproxy/src/index.ts) 构造 `createApiProxy` 时注入：

```text
defaultModelSelection: () => ctx.agentDefaultModel.currentSelection()
saveDefaultModelSelection: (s) => ctx.agentDefaultModel.saveSelection(s)
```

用途拆分：

| 钩子 | 何时用 |
|------|--------|
| `defaultModelSelection` | 每次 `agentOptions()`（create/resume seed）；`selectionFor` 在**无日志**时的 fallback |
| `saveDefaultModelSelection` | 用户在 Models 页改**默认**模型；会话内切换模型时也会尝试写默认（失败只 warn，会话内仍生效） |

ApiProxy **不**持有自己的 provider/model config；避免与 headless 分叉。

## base bundle  wiring

[`dsh-base` cordis.patch.yml](../../../bundle/base/cordis.patch.yml) 顺序要点：

```text
agent-default-model   ← 组合 provider/model
…
settings-file         ← 用户 settings.yaml，可覆盖 agent-default-model 分节
```

注释写明：Settings 可供给已保存的选择；消费方在**创建时**读取。

## 不要做的事

- 在入口里再硬编码 `{ provider, model }` 当第二套默认；
- 假设 `saveSelection` 在无 Settings 时仍会持久化；
- 以为改了默认会改掉**已有 session 日志**里的模型（见下一章）。
